# 0002: Discovery documents as Go pins them, a generator in Xo

Status: Accepted (by the owner, through the lead, 2026-11-07).

## Context

Go's REST packages are generated by google-api-go-generator from each
API's Discovery document (`restDescription`: `rootUrl`, `servicePath`,
`parameters`, `resources` with nested `methods`, `schemas`, `auth`
scopes, `mediaUpload`, `supportsMediaDownload`). Go commits the exact
document it generated from into the package
(`<api>/<version>/<api>-api.json`), so the module cache of a Go release
holds every input.

## Decision

- The spec of every module is the Discovery JSON in Go's own package at
  Go's newest google.golang.org/api release, read from the Go module
  cache (the Go module proxy; never a Google API endpoint, and never
  the live Discovery service, so a module and Go always share their
  input).
- The generator is written in Xo (`codegen/`), reads the documents and
  writes each module; generated code is committed, and regenerating
  must leave it unchanged (a `check-generated` gate step), as in the
  AWS and Azure ports.
- The generator's per-API data (`codegen/services.toml`, one row per
  API version: Go's package path, Go's version, the document's path)
  is itself derived from Go's module by a tool (`codegen/gorows`), never
  written by hand; a refresh script runs the whole chain
  ([0006](0006-bulk-rules.md)).
- Naming follows google-api-go-generator's own rules (its Go names for
  resources, methods, schemas and parameters, its handling of
  reserved words and name clashes), ported into the generator, in
  Xo's casing (`snake_case` functions, `PascalCase` types).
- What the generator does not handle is printed, never dropped.

## Consequences

- No separate spec checkout and no spec fetching: Go's module is the
  spec cache.
- A Discovery feature the generator lacks shows as a failure class
  across every API that uses it, fixed once.

## Alternatives

- The live Discovery service (`https://www.googleapis.com/discovery/v1/apis`):
  its documents change daily and would drift from what Go ships, and it
  is a network call to Google from the build.
- Port google-api-go-generator and run it in Go: the port's generator
  is Xo code, which is part of what the port proves.
