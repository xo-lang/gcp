# v0.2.0

The second release of the Google Cloud SDK for Xo: the root module
(`github.com/xo-lang/gcp`), the hand-written `storage` and `bigquery`
clients, and all 667 API modules, 670 in all, tagged v0.2.0 at one
commit. Released with Xo 0.51.0; requires Xo 0.51.0 or later.

A community SDK for the Xo language. Not affiliated with or endorsed by
Google. Google Cloud is a trademark of Google LLC.

## Upgrading from v0.1.0

- **New module paths** (decision 0012, breaking). Each API version is an
  `apivN` path element, so `github.com/xo-lang/gcp/storage/v1` is now
  `github.com/xo-lang/gcp/storage/apiv1` and `bigquery/v2` is
  `bigquery/apiv2`. Rename your `use` lines and `xo get` paths. The old
  paths keep their v0.1.0 tags and get no new versions; the 91 modules
  at `/v2` and above could not be required at all before (XO1301).
- **Xo 0.51.0 or later.** Model fields that never go into a model's own
  JSON use `as "-"` (xo decision 0622), which an older Xo reads as a
  field named `-`.

## Empty values and null in a request body

Every field is left out of a request body when it is empty, as in Go.
A PATCH that must send `[]`, `null`, `false` or `0` names the field in
the model's `force_send_fields` or `null_fields` (Go's ForceSendFields
and NullFields, [decision 0013](../decisions/0013-force-send-null-fields.md)),
typed by a generated enum of the model's fields:

```xo
let ev = calendar.Event{
  force_send_fields: [calendar.EventField.Attendees, calendar.EventField.Recurrence],
  null_fields: [calendar.EventField.ConferenceData],
  reminders: Some(calendar.EventReminders{
    use_default: false,
    force_send_fields: [calendar.EventRemindersField.UseDefault],
  }),
}
// PATCH body: {"attendees":[],"conferenceData":null,"recurrence":[],"reminders":{"useDefault":false}}
```

Nested models have their own lists, and `gensupport.json_body` applies
them at every level. A program that built these bodies by hand (a raw
PATCH for Calendar reminders, attendees, conferenceData, recurrence or
attachments, or `trashed: false` through Drive's `files.update`) can use
the generated call instead.

## New since v0.1.0

- `storage` (decision 0010): Go's Cloud Storage client: handles,
  attributes, listings, readers and writers (resumable, CRC32C),
  copy and compose, ACLs, HMAC keys, notifications, IAM, signed URLs and
  POST policies, lifecycle, retention and soft delete.
- `bigquery` (decision 0011): Go's BigQuery client: datasets, tables,
  routines, models, queries and rows (`RowIterator`, `ValueLoader`),
  every value type including NUMERIC and BIGNUMERIC, the streaming
  inserter, and copy, extract and load jobs.
- `auth`: the token cache, the metadata server, service account and
  user grants, credential files and Application Default Credentials
  (decision 0009); `compute/metadata`.
- The full list is in [CHANGELOG.md](../../CHANGELOG.md).

## How it is checked

Every method of every API module is called in Go and in Xo with the
same arguments against the same fake service, and the requests, the
responses served and the decoded results are compared; `storage`,
`bigquery` and `auth` replay Go oracle cases over a fake network. No
test calls Google Cloud.

## Install

    xo get github.com/xo-lang/gcp@v0.2.0
    xo get github.com/xo-lang/gcp/calendar/apiv3@v0.2.0

Get the API versions your program uses; each requires the root at v0.2.0.
